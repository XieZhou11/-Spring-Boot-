## 后续设计

- 数据库设计按当前需求审核；真实 MySQL 迁移及初始化失败补偿已验证；索引效果、业务事务与并发行为在后续对应业务功能中验证。
- 图片列表使用 JSON，交易快照、条件唯一约束及统一锁定顺序见数据库设计；变更时同步字段说明与迁移。
- 架构、数据库、接口和 UI 说明在有实际内容时再创建，不预建空文档。简单局部设计随对应业务功能任务维护；重要且独立的选择再记录 ADR。

## 编写要求

- 写明草稿、已确认或已废弃状态、更新日期和需求依据；有关联的业务功能任务时再添加任务链接。
- 区分需求已规定的行为、设计选择和仍需决策的问题，不把建议伪装成事实。
- 给出边界、接口、异常和验证方式；涉及交易时明确事务、并发及恢复策略。
- 简单局部设计可放入任务文档，避免为每个小改动生成独立长文。
- 纯设计或目录维护直接更新已有文档，不创建开发任务、实施计划或测试记录。
- 接口地址、方法、参数、返回字段与错误码随相关任务设计及代码实现维护，不设独立接口契约目录；迁移脚本在后端工程初始化后按实际需要组织。
- 设计变更同步相应任务和受影响的接口、测试及运行说明。

# 测试结果记录

本目录只保存实际业务功能开发或业务缺陷修复的简短测试结果：测了什么、通过还是失败、必要的问题说明。账号后端验证见 [T-001 测试记录](T-001-backend-auth.md)，认证页面联调见 [T-002 测试记录](T-002-frontend-auth.md)，个人资料、头像与地址联调见 [T-003 测试记录](T-003-personal-center.md)，创作者入驻、审核及通知见 [T-004 测试记录](T-004-creator-onboarding.md)，作品发布、审核及浏览见 [T-005 测试记录](T-005-work-publication.md)，作品互动及个人收藏、关注列表见 [T-006 测试记录](T-006-work-interactions.md)。

## 存放方式

- 记录直接放在本目录，不建子目录，不单独拆测试计划、覆盖矩阵或证据目录，也不存测试代码。
- 文档修改、目录整理、技术选型、框架初始化及纯设计不在此创建检查记录；文档链接检查、AI 自查或空工程构建不记作业务功能测试。
- 按对应业务任务命名；同一任务包含多个功能点时，在同一份记录中分行填写。
- 同一任务或功能点的复测追加到原记录，保留失败原因和后续结果，不为每次复测新建文件。
- 任务文件只写总体结果并链接这里的记录，避免重复维护详细结果。可执行测试以后放在对应前后端工程内。

## 最小记录格式

复制下面的格式填写即可，无需额外模板文件：

```markdown
# T-编号 任务或功能名称测试记录

- 关联任务：链接到对应任务文件
- 环境或前提：仅填写影响结果的必要信息

| 日期 | 测试项与命令或操作 | 结果 | 简要说明 |
| --- | --- | --- | --- |
| YYYY-MM-DD | 填写实际检查内容 | 通过 / 失败 / 未执行（三选一） | 失败写原因；未执行写原因；复测说明处理结果 |
```

仅凭实际执行结果填写“通过”或“失败”；未运行的项目写“未执行”。日志仅摘录必要报错，不保存大量原始输出或真实个人信息。

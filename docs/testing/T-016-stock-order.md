## 过程中的失败及修正

- 首次新增超时夹具使用 MySQL 不支持的 `INTERVAL 1 MILLISECOND` 写法，数据库拒绝执行；改用 `INTERVAL 1 SECOND` 后专项复测通过。
- 通知写入故障通过随机隔离 MySQL 触发器注入，验证事务回滚覆盖订单、库存、会话、通知与操作日志。
- 浏览器用例首次在地址组件已挂载后才创建地址，购买按钮因没有已加载地址保持禁用；将地址准备移至作品详情打开前。
- 浏览器发货用例误点“填写运单并发货”入口重置表单，导致运单未提交；改点表单内“确认发货”。随后既有作品主页断言基于作品详情路由，在订单流程后重新打开作品详情继续验收。
- 结果未知后的恢复检查发现：建单成功但响应丢失时，作品已显示为 RESERVED，原页面按 `purchasable=false` 隐藏了重试入口。现保留该作品对应的原请求重试面板，使买家可在刷新后复用请求键核验同一订单。
- 首次并行执行前端检查与后端测试导致 Node 内存耗尽及测试 JVM 异常退出；改为串行执行。该次不是业务断言失败。

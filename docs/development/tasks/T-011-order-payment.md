- 关联设计：[数据库表结构](../../design/数据库表结构.md)订单、资金流水、结算、制作节点及统一事务锁序；承接[T-009](T-009-quote-award.md)。

## 目标与范围

在已有订单详情内确认条款并模拟付款，原子生成成功支付流水、待结算记录和固定五节点计划，订单进入待开工、需求进入交易中，双方可查询结果并收到通知。本次不提供开工、打卡、现货购买、退款或结算执行；这些仍属于当前MVP，后续独立验收。沿用V1—V5，不新增迁移。

## 验收条件

- 仅本单买家支付CUSTOM订单；当前新业务暂停、原作品或品类变化、原报价到期不阻止旧单付款，现货入口保持隔离。
- 服务端取订单成交金额；锁后重检身份、关联、状态和24小时截止，已成功支付优先返回原结果，重复或并发不多记账。
- 支付、PAID、IN_TRADE、PENDING结算、已审核收款资料密文快照、五节点、条款依据、历史与双方通知一起提交或回滚；付款与取消仅一个生效。
- 五节点均NOT_STARTED，初始日期和最终发货截止按实际支付北京日期计算并固定，不修改原方案、地址或定标预计日期。
- 订单查询不写业务，同一响应读取一致快照；列表不返回地址、完整条款、流水明细及节点，买家不读取收款资料，创作者本阶段不读取完整地址。
- 页面真实付款、未知结果核验/刷新恢复、旧查询竞争及多端状态同步可回归；关键事务、截止和并发用隔离MySQL验证。

## 设计与接口约定

新增独立支付Service，职责包保持平级。支付写事务READ_COMMITTED，用户编号升序→需求→订单→所需下游记录的锁序与取消一致；获得锁后取一次毫秒精度北京时间。查询使用只读一致快照。资金幂等键为`PAYMENT:ORDER:{id}`，每单唯一成功PAYMENT、唯一结算及唯一五节点由已有约束兜底。

| 方法与路径 | 约定 |
| --- | --- |
| PUT /api/orders/{id}/payment | termsConfirmed=true、termsVersion、confirmedShipDate；首次201、重复成功200，返回最新OrderVO；不接收客户端金额 |
| GET /api/orders/{id} | 原详情扩展付款预览、支付结果、结算摘要及初始计划，也是未知结果查询入口 |
| GET /api/me/orders | 增加PAID筛选和支付摘要，保持原分页及买卖关系 |

付款DTO用普通类及标准Jakarta校验；未付款时条款版本或确认日期已变化返回409，成功重试先返回原支付。到达付款截止拒绝且零资金写入，原扫描落库取消。陌生人或现货404，本单创作者403；管理员不能交易。未付款实付为null。金额为两位小数字符串，编号字符串，时间含+08:00。

OrderVO增加canPay、paidAmount、paidAt、termsConfirmedAt、shipDate、shipDeadlineAt、paymentPreview、payment、settlement、progressNodes。paymentPreview含shipDate、shipDeadlineAt、termsVersion、termsText，仅买家待付款详情返回。payment含flowNo、amount、result、occurredAt、termsVersion、termsText，仅双方详情返回。settlement含paidAmount、status、maskedPayee，仅创作者返回。progressNodes含id、nodeCode、sortOrder、plannedFinishDate、status、handledAt，仅详情返回。

实际支付北京日期P、工期N：最终发货日=P+N；shipDeadlineAt=(P+N+1)00:00，作为排他截止。累计节点日=P+ceil(N×[15,35,80,90,100]/100)，不提前解锁。原定标预计日期保留。

付款条款固定版本`CUSTOM_PAYMENT_V1`，说明模拟不扣款、工期从支付次日按自然日起算且含开工等待、开工后不支持单方无理由退款、满48小时未开工可申请无责全额退款的规则。条款原文及版本存PAY操作历史，服务器保存terms_confirmed_at；本阶段不宣称退款已实现。支付时冻结已审核申请的姓名、申请编号和账户密文，后续结算沿用快照。

ORDER_PAID通知同事务保存、提交后推送；关联会话提交后通知状态更新，不重建会话。日志记录阶段、用户/订单/流水编号和状态，不输出请求体、地址或收款资料。

前端复用/orders及/orders/:id，内嵌付款确认；按用户/订单在sessionStorage保留待核验确认参数，不存地址、金额或账户。提交/结果未知时禁取消；网络和5xx先核验不宣称失败，待付款查询不能证明原请求失败。旧响应不得覆盖新状态；401/403/404清除敏感视图，临时读取失败保留上下文。通知、连接恢复及页面恢复触发持久化核验，保留原通知Store改动。

## 审查与遗留问题

当前范围无遗留阻断问题。未知付款查询不能因无流水的取消投影而清除确认；浏览器存储失败不能发送付款或锁死页面，权限失效清除敏感上下文。两项审查问题已修复并复审。没有开工、打卡、退款或结算执行能力，本次仅验收支付初始化。本轮未提交Git，保留原有工作区改动，未主动迁移开发库。

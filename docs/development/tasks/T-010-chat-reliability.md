# T-010 聊天连接可靠性与查询优化

- 状态：已完成
- 更新日期：2026-11-17
- 需求依据：[V1.5](../../requirements/requirements.md)4.8.2—4.8.4，消息先存后推、多端同步、离线补拉、有限重连与登录凭证鉴权。
- 关联设计：[T-007 会话接口](T-007-custom-requests.md)，沿用 HTTP 写入和 `/api/ws` 推送。

## 目标与范围

修复实时连接无响应时无法及时恢复的问题，减少其他会话及连续事件引起的重复查询，合并同一用户多端连接的凭证查询。保持原有会话权限、消息持久化、幂等、已读和补拉规则；不改变数据库或报价、订单业务范围。

## 验收条件

- WebSocket 建立后发送心跳，收到PONG后20秒再次发送；10秒未收到PONG时主动释放旧连接并有限重连，不能等待旧连接关闭握手完成。
- 重连仍最多自动重试5次；持续连接至少30秒且收到有效PONG才恢复重试额度。退出、账号切换、登录过期后清理心跳/重试计时器，旧连接事件不能污染新账号。
- 初始持久化未读查询独立于实时握手；握手失败仍显示已有未读，连接成功再次核对期间变化。
- 当前会话不因其他会话事件重新查询消息；100毫秒内连续聊天事件合并刷新，会话列表和未读仍及时更新。
- 同会话消息、已读、归档及重连仍同步；独立HTTP补拉游标、历史分页和发送幂等不变。
- 每轮凭证扫描及每次用户推送，对同一用户最多执行一次凭证查询；结果不跨轮缓存，每个连接仍核验自身Session与有效期。
- 真实MySQL/HTTP/WebSocket验证退出、改密、到期和消息收发；浏览器验证心跳超时恢复、重试上限、按会话刷新及原有聊天交互。

## 设计与改动位置

- `frontend/src/stores/notifications.ts`：连接生命周期、心跳与有限重试；按会话收集事件，批次发布刷新信息。
- `frontend/src/views/ConversationDetailView.vue`：仅响应当前会话或重连后的全量核对，保留独立补拉游标。
- `frontend/src/views/ConversationsView.vue`：沿用批次刷新列表，合并在途刷新，避免重复未读查询。
- `backend/.../security/NotificationSocketHandler.java`：凭证查询结果仅在本轮扫描/推送局部共享，继续逐连接核验会话及有效期。
- 后端本地测试验证实际SQL查询次数和真实连接安全行为；`frontend/e2e/chat-reliability.spec.ts`保存浏览器回归，故障注入仅存在于测试。

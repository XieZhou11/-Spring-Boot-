## 目标与范围

完成 QQ/163 邮箱验证码、注册、邮箱密码登录、当前会话查询与退出、密码重置。注册填写昵称；采用现有 HttpSession、BCrypt 和两张账号相关表，不改写 V1。前端认证页面在 [T-002](T-002-frontend-auth.md)接入；身份切换、个人资料编辑和 WebSocket 连接随对应功能实现。

## 验收条件

- 邮箱规范化后唯一，仅支持 qq.com、163.com；密码 8—20 位含字母数字且无空白，昵称 2—8 字。
- 六位验证码五分钟有效、最新一次有效、成功使用即作废，注册和重置共用；发送失败或未知不假成功。
- 创建账号/更新密码与消费验证码同事务；重复和并发请求不能创建重复账号或重复消费。
- 多端登录互不挤出，七天绝对有效期，退出当前会话即失效；重置后全部旧会话失效。
- 保留 Cookie、CORS、CSRF 防护，身份由服务端确定，两种暂停均不阻止登录。
- 各业务在 Service 关键节点记录开始、关键校验、结果和失败阶段，控制台可定位错误；参数校验、安全拒绝和邮件故障也有提示，不输出密码、验证码、邮箱用户名、会话或 SMTP 凭据。
- 实际 MySQL 事务与 HTTP 闭环测试通过；QQ、163 实收须有真实 SMTP 配置后验证。

## 设计与改动位置

代码在后端 `modules` 下同级 controller/service/serviceImpl/mapper/dto/vo/entity/security/exception 包；Controller 依赖 Service 接口，业务实现放在对应的 ServiceImpl，事务注解放实现方法上。请求使用以 DTO 结尾的普通 Java 类，校验注解直接声明在 DTO 字段，通过 @Valid 触发；Entity、DTO 每个字段及 VO 返回字段均说明含义，统一 Result 响应。验证码先短事务保存 SENDING，再事务外 SMTP，最后按发送请求键更新；消费在账号变更事务内加行锁。会话保存密码摘要指纹并在认证请求核对，重置提交后撤销原会话，防止并发登录漏撤销。

| 方法与路径 | 请求字段 | 成功结果 |
| --- | --- | --- |
| POST /api/email-verification-codes | email | 201：expiresAt |
| POST /api/accounts | email、verificationCode、password、nickname | 201：userId、email、nickname |
| POST /api/sessions | email、password | 201：当前会话 |
| GET /api/sessions/current | 无 | 200：当前会话 |
| DELETE /api/sessions/current | 无 | 200：data=null |
| POST /api/password-resets | email、verificationCode、newPassword | 200：data=null |

当前会话包含 userId、email、nickname、roles、activeRole、expiresAt。时间使用带北京时间偏移的 ISO-8601 字符串，编号以字符串返回。所有写请求先读取 /api/csrf 并携带同一 Cookie 与令牌。

业务错误码：40001 验证码无效，40002 邮箱未注册，40101 邮箱或密码错误，40901 邮箱已注册，40902 发送被新请求替代，50201 邮件明确失败，50301 邮件/验证码密钥未配置，50302 发送或保存结果未知。通用错误码保持不变；字段校验 40000，data.fieldErrors 返回 field/message，不含原始输入。

日志以 Service 实现层的业务关键节点为主，公共异常处理器和安全过滤链补充 HTTP 请求与拒绝信息。注册、登录、会话查询、退出、验证码发送/核验及密码重置记录关键过程和结果；业务失败 WARN，技术故障 ERROR，正常过程 INFO。失败标明业务阶段和原因，账号事务提交后才记录成功；密码提交与旧凭证撤销分别记录。邮件按发送请求键关联，异常栈移除原始消息。默认只输出控制台，移除文件日志及滚动归档配置；后续所有业务遵守 AGENTS.md 中同一约定，查阅方法见后端 README。

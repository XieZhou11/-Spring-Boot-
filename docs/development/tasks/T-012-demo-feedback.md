# T-012 主流程演示反馈修复

- 状态：已完成
- 更新日期：2026-11-19
- 需求依据：[V1.5](../../requirements/requirements.md) 的需求、报价、订单与消息规则；[主流程演示报告](../../testing/demo-main-flow.md)第 3 节及用户授权的反馈修复。
- 关联设计：沿用 T-007、T-009、T-010、T-011 的接口、权限与状态，无数据库或接口变更。

## 目标与范围

修复需求、报价及订单页面离开时的空编号查询、管理员多余聊天未读查询；让需求与订单提示对应当前业务状态，改善 PC 订单摘要字段排版。保持现有正向演示流程及系统通知，不新增尚未实现的履约功能。

## 验收条件

1. 从需求详情、报价对比、订单详情离开或切换对象时，不发送空编号请求；返回后能读取正确对象，未知付款确认继续按原订单恢复。
2. 管理员保留系统通知与实时连接，不查询聊天未读；普通买家及创作者继续核对聊天未读，同账号资格更新不沿用旧状态。
3. 无有效报价过期说明只在开放阶段出现；交易进行中与已付款待开工不再显示结束或取消提示。
4. PC 订单金额与日期标签可读，窄屏无页面横向溢出；付款、取消及消息相关浏览器回归通过。

## 设计与改动位置

- `CustomRequestDetailView.vue`、`QuoteComparisonView.vue`、`OrderDetailView.vue` 和路由：读取前核对所属页面与有效编号，继续隔离旧响应。
- `App.vue`、通知 store：以账号及真实管理员资格维护连接作用域，系统通知与聊天权限分别处理。
- 需求/订单详情及 `quote.css`：按状态呈现提示，局部加宽摘要字段标签。
- `frontend/e2e/`：保存导航与通知缺陷回归，复用真实后端夹具及现有支付流程。

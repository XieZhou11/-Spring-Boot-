# 开发与任务管理

本目录只记录实际业务功能开发和业务缺陷修复，用任务连接需求、实现、验证和交接。任务按可验收的业务结果划分。

## 当前记录

已有 [T-001 后端账号注册、登录与找回密码](tasks/T-001-backend-auth.md)及 [T-002 认证页面联调](tasks/T-002-frontend-auth.md)，覆盖真实接口、会话与登录/注册/找回页面；QQ/163 公网实收验收需要发件凭据。后续业务功能按[任务模板](tasks/TASK_TEMPLATE.md)创建独立验收任务。

## 任务约定

- 命名为 `T-编号-英文主题.md`，编号在本目录中保持唯一。
- 需求讨论或修订、文案格式调整、目录整理、协作规则调整、技术选型、框架初始化、纯数据库或架构设计不创建任务及对应检查记录；直接修改已有需求、设计、README 或 AGENTS.md。
- 状态使用：待开始、进行中、受阻、待验收、已完成。已完成必须有实际验证记录。
- 需求引用相关章节或已有 `UC-*` 验收编号；新增规则先补充明确依据。
- 任务只维护该业务功能的目标、边界、实现、实际验证和交接，不加入无关工作日志、聊天摘要或工具操作过程。
- 任务或功能点的详细测试结果直接放在 [docs/testing/](../testing/README.md)，按日期简记测试项、通过或失败及必要说明；任务中只写总体结果和记录链接，不重复维护详细表格。
- 计划中的步骤要指向具体交付物和验证方式，任务开始后按实际情况更新。
- 完成后默认保留工作区改动，只有用户明确要求提交代码时才创建 Git 提交。未提交时记录“未提交”和相关文件，不能编造提交编号。

## 执行方式

```text
读取依据 → 明确验收 → 局部设计与计划 → 实现和检查
        → 审查与修正 → 记录证据与交接
```

业务功能任务内的常规工作连续推进。遇到无法确定且影响正确性的业务问题时记录并澄清，同时继续不依赖该结论的工作。业务缺陷先复现、定位，再修复。文档及格式修改按需检查，不另建任务或测试记录。

新聊天从任务文件恢复上下文。交接至少指出实际完成内容、执行的检查、遗留问题和下一步入口。

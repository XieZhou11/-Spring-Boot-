- 计划中的步骤要指向具体交付物和验证方式，任务开始后按实际情况更新。
- 完成后默认保留工作区改动，只有用户明确要求提交代码时才创建 Git 提交。未提交时记录“未提交”和相关文件，不能编造提交编号。

## 执行方式

```text
读取依据 → 明确验收 → 局部设计与计划 → 实现和检查
        → 审查与修正 → 记录证据与交接
```

业务功能任务内的常规工作连续推进。遇到无法确定且影响正确性的业务问题时记录并澄清，同时继续不依赖该结论的工作。业务缺陷先复现、定位，再修复。文档及格式修改按需检查，不另建任务或测试记录。

新聊天从任务文件恢复上下文。交接至少指出实际完成内容、执行的检查、遗留问题和下一步入口。

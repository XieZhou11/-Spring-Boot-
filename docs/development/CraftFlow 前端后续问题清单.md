# CraftFlow 前端后续问题清单

复核日期为 2026-11-26，代码基线为 `91f9723`。后续 CraftFlow 前端修复以本清单为入口，复现步骤和通过标准随对应条目查阅。清单收录两份前端审查报告的共同发现，以及对附件条目复核后确认的缺陷、适用条件和回归检查。R、L、I 编号沿用《前端代码审查报告（布局渲染 / 交互逻辑 / 路由）》。

当前表现来自源码核查或 Chrome、Edge 的定向复现。浏览器复现使用模拟 API 或 WebSocket 响应。以下通过标准均为后续验收预期，修复完成后在对应任务中引用本清单条目，并关联实际测试结果。建议先处理 R2、R4、I4、I5。业务规则及桌面验收范围以 V1.5 为准。 [需求正文](../requirements/requirements.md) · [前端重做开发指南](../design/frontend-rebuild-guide.md)

## 一、待修复问题

### R2 · 会话核验临时失败时跳转登录

- **复现与当前表现**　用有效会话进入作品广场，让下一次 `GET /api/sessions/current` 断网、超时或返回 503，再点「我的订单」。已复现跳至带 `reason=connection` 的登录页。守卫会清除内存会话，连带清理聊天草稿等状态。
- **通过标准**　已有会话时，临时核验失败显示连接错误，保留当前页面可保留的输入，并可重试原目标。恢复网络后能进入原目标，保留查询和锚点。首次访问受保护页时，身份核验前不展示受保护内容。真实 401 仍进入登录并在登录成功后回到原目标。持续失败时无跳转循环。 [路由守卫](../../frontend/src/router/index.ts#L129) · [会话清理](../../frontend/src/stores/auth.ts#L24)

### R4 · 页面懒加载失败时白屏

- **复现与当前表现**　使用生产构建，阻断作品广场的 JS 模块，然后从地址栏首次打开首页。已复现应用容器为空。验收也覆盖已打开页面后，点击尚未加载的站内路由。
- **通过标准**　首次加载和站内跳转失败均给出可见提示与重试入口。网络恢复后可进入原目标，路径、查询和锚点保留。持续失败时提示仍可操作，页面不会反复自动刷新。 [路由配置](../../frontend/src/router/index.ts#L5)

### I4 · 入驻申请草稿误离开后丢失

- **复现与当前表现**　普通买家开始入驻申请，填写姓名，点击个人中心的「个人资料」，再返回入驻页并开始申请。已复现没有离页确认，姓名恢复为空。复测时另加入已上传测试图片，并覆盖浏览器刷新和关闭标签页。
- **通过标准**　有未保存改动时，站内离开及浏览器支持的刷新、关闭场景会给出确认。取消后保留已填字段和已上传材料。确认离开才丢弃草稿。未修改或已完成操作的页面可正常离开。上传进行时的行为有明确反馈，收款资料继续保存在页面内存。 [CreatorCertificationView.vue](../../frontend/src/views/CreatorCertificationView.vue#L49)

### I5 · 交易设置更新成功后残留字段错误

- **复现与当前表现**　打开一件已上架作品，启用现货，填售价 `0` 并点击即时更新。出现售价错误后改填 `20.00` 再更新。已复现接口成功、页面显示更新成功，售价仍显示旧错误，`aria-invalid` 仍为 `true`。
- **通过标准**　无效售价或定制周期显示对应错误，写请求数为 0。修正并更新成功后，对应错误及无效标记清除。标题、描述等未保存的展示内容继续保留。切换现货和定制选项、模拟更新失败时，分别检查对应字段和反馈。 [WorkEditorView.vue](../../frontend/src/views/WorkEditorView.vue#L180)

### R1 · 浏览器后退丢滚动位置，直接打开锚点未定位

- **复现与当前表现**　在作品广场应用筛选，滚到第 18 件作品，进入详情后浏览器后退。Edge 实测 `scrollY` 从 2276 回到 0，筛选仍在。另在地址栏首次打开 `/#discover`，已复现页面停在顶部，结果区仍在距视口顶部约 246px 的位置。
- **通过标准**　浏览器后退恢复原筛选和页码，等列表实际渲染后恢复原阅读位置。直接打开有效锚点能定位到目标区，标题完整可见。订单进度、公开授权、需求报价的已有锚点继续可用。广场正常翻页回到新页顶部。 [路由配置](../../frontend/src/router/index.ts#L5) · [广场结果锚点](../../frontend/src/views/HomeView.vue#L259)

### R5、R6 · 无效链接和资源编号缺少一致反馈

- **复现与当前表现**　分别打开不存在的路径、`/requests/invalid/quotes`、`/admin/refunds/abc`、`/works/not-an-id`。当前分别静默回到广场、只展示报价标题、只展示售后工具栏、向接口发送无效编号。
- **通过标准**　未匹配路径有页面不存在提示及返回入口。非法编号在进入业务查询前被拦截，详情请求数为 0。合法编号对应资源不存在、无权访问或短时读取失败时，分别有相应反馈。有效详情、旧书签和登录回跳保留其查询与锚点。 [兜底路由](../../frontend/src/router/index.ts#L124) · [报价详情](../../frontend/src/views/QuoteComparisonView.vue#L25) · [售后详情](../../frontend/src/views/AdminRefundDetailView.vue#L22)

### R7 · 定向邀约通知打开详情后返回入口错误

- **复现与当前表现**　用受邀创作者账号点开 `REQUEST_INVITED` 通知的「查看需求」。已复现到达需求详情后，工作台侧栏缺失，面包屑指向该创作者自己的「我的需求」。
- **通过标准**　受邀创作者从通知打开后能查看详情，并返回「收到的邀约」。本人需求通知返回「我的需求」。从已筛选的大厅或邀约列表进入时保留原筛选和页码。无效来路回到当前关系可访问的入口。资源资格仍由服务端核验。 [通知跳转](../../frontend/src/views/NotificationsView.vue#L58) · [需求详情来路](../../frontend/src/views/CustomRequestDetailView.vue#L24)

### I2 · 同一次恢复页面触发重复查询

- **复现与当前表现**　打开带售后记录的订单详情，等首屏读取结束，在同一次激活中触发 `focus` 和可见性恢复。受控复现共 9 个 GET，其中订单详情、订单列表和售后列表各请求两次。
- **通过标准**　同一次激活中的相同账号、资源和参数在途 GET 合并为一次。单独触发两种事件也能正常刷新。会话核验、不同资源读取、断线补拉、实时更新和手动重试继续工作。切回页面后已展开的售后证据、已勾选材料和阅读位置仍可用。 [订单详情刷新](../../frontend/src/views/OrderDetailView.vue#L288) · [订单列表刷新](../../frontend/src/components/OrderCollection.vue#L100) · [售后刷新](../../frontend/src/components/OrderRefundPanel.vue#L142)

### I10 · 广场重试读取未应用的筛选

- **复现与当前表现**　先按一个关键词搜索，再模拟翻页读取返回 503。在错误页输入另一关键词，直接点击「重新读取」。已复现新关键词被写入 URL，查询仍使用旧页码。
- **通过标准**　「重新读取」重放地址栏已应用的条件及页码。用户明确执行新筛选才更新 URL，并从第 1 页开始。读取失败时旧卡片、旧总数和分页控件保持隐藏，恢复后展示与 URL 对应的结果。 [HomeView.vue](../../frontend/src/views/HomeView.vue#L265)

### L5 · 部分业务分页的可访问名称错误

- **复现与当前表现**　准备超过一页的需求，打开需求列表，在 DOM 或浏览器可访问性树检查分页导航。需求分页实测名为「作品分页」。订单和通知分页分别使用正确的「订单分页」「通知分页」。
- **通过标准**　用多页数据检查需求、报价、评论及退款等共用分页入口，导航名称与业务内容对应。订单和通知继续使用各自正确的名称。 [共享分页组件](../../frontend/src/components/WorkPagination.vue#L6) · [需求列表调用处](../../frontend/src/components/RequestCollection.vue#L335)

### 布局附项 · 退出失败提示长期遮挡内容

- **复现与当前表现**　在 1366×768 视口打开有右侧交易摘要的前台页面，模拟退出失败后滚动。Edge 实测提示浮层持续覆盖页头下方约 y64 至 y106，命中测试落在浮层而非下方内容。
- **通过标准**　退出失败时有明确提示，会话继续有效。提示可关闭或在页面布局中占据自己的空间。滚动时下方链接和按钮仍可操作，用户可以重试退出。 [页头提示](../../frontend/src/components/BusinessHeader.vue#L132) · [提示样式](../../frontend/src/assets/styles/navigation.css#L154)

## 二、边界修复与可选优化

### I3 · 无效签名时间触发快速重复续签

- **复现与当前表现**　让同一张作品图的前三个签名成功响应返回不可解析的 `expiresAt`，第四个响应给合法值。已复现 650ms 内发出四次读取，收到合法值后快速重试停止。正常图片接口使用 `OffsetDateTime`。
- **通过标准**　缺失或非法时间不会造成密集续签，用户仍可手动重试。合法时间照常续签，列表中一个异常项不影响其余图片。离开页面撤销本页计时。 [图片组件](../../frontend/src/components/WorkImage.vue#L23) · [接口字段类型](../../backend/src/main/java/com/handcraft/platform/modules/vo/ImageVO.java#L6)

### I6 · 历史材料持续读取失败时无法审核

- **复现与当前表现**　打开有上次申请的入驻审核，模拟历史材料请求失败。通过和驳回按钮禁用。已实测首次返回 404 后，点击「重新读取材料」，历史材料返回 200 时按钮恢复。持续返回 403 或 404 时没有绕过入口。
- **通过标准**　首申能按无历史办理。有历史时展示当前材料、历史结论和本次变化。短时失败有提示和重试，恢复后可以审核。持续失败时明确缺失的材料，并保留申请定位和排查入口。是否允许跳过历史继续裁定属于产品规则，V1.5 未定义该例外。 [审核重试](../../frontend/src/views/AdminCreatorReviewView.vue#L94) · [审核要求](../requirements/requirements.md#L694)

### I7 · 验证码发送完成后缺少冷却反馈

- **复现与当前表现**　在注册或找回密码页发送验证码，成功后立即再次点击。当前只锁定在途请求，发送完成后可再次发送。邮箱接口当前没有固定冷却或 `Retry-After`，显式使用该响应头的是聊天限流接口。
- **通过标准**　现有规则应覆盖发送在途防连点、换邮箱后反馈与当前邮箱一致、发送失败或未知如实提示、重发后旧码失效。若采用固定冷却，由服务端定义期限和剩余时间，页面倒计时及切页、刷新后的状态与服务端一致。 [验证码按钮](../../frontend/src/components/VerificationCodeButton.vue#L36) · [邮箱验证码服务](../../backend/src/main/java/com/handcraft/platform/modules/serviceImpl/EmailVerificationServiceImpl.java#L94) · [V1.5 验收](../requirements/requirements.md#L881)

### R3 · 创作者资格拦截后缺少原目标

- **复现与当前表现**　普通买家直接打开 `/creator/works` 或 `/requests`，守卫转到入驻页，原目标没有保留。认证可以跨多次访问完成。
- **采用后的通过标准**　资格生效后可继续前往原站内目标。检查目标白名单，并按目标路由重新核验资格。仍未获资格、目标已失效或目标为外部地址时，使用合法入口且无跳转循环。 [创作者守卫](../../frontend/src/router/index.ts#L144)

### I8 · 列表筛选和页码的恢复方式不一致

- **复现与当前表现**　准备多页数据，在通知、我的报价、收入、我的作品、会话或认证历史翻到第 2 页再刷新。页码回到第 1 页。认证历史的 `applicationId` 已写入 URL，仍能独立恢复所选申请。
- **采用后的通过标准**　刷新、后退、重新打开链接均恢复约定的已应用筛选和页码。越界时回到有效页。认证历史独立恢复所选申请和列表页码。换账号后按新账号重查，页面只展示其可访问的数据。 [通知翻页](../../frontend/src/views/NotificationsView.vue#L88) · [认证历史](../../frontend/src/views/CreatorCertificationView.vue#L83)

### I9 · 订单内「查看原需求」缺少需求列表来路

- **复现与当前表现**　从 `/my-requests?status=OPEN&page=2` 进入需求和报价对比，用模拟成功响应定标。订单页的「查看原需求」直接打开需求详情。浏览器后退仍可恢复原报价 URL 及其 `returnTo`。
- **采用后的通过标准**　现有「查看原需求」链接可在有安全来路时恢复原需求列表筛选和页码。直接打开订单、无来路、非法来路均有合理入口。「返回订单列表」继续保留订单列表的返回语义。 [定标跳转](../../frontend/src/views/QuoteComparisonView.vue#L94) · [查看原需求](../../frontend/src/views/OrderDetailView.vue#L715)

### I1 · 原生确认框的兼容性与交互一致性

- **触发条件与当前表现**　源码有 27 处 `window.confirm`。正常浏览器场景可确认或取消。若浏览器抑制站点弹窗，依赖确认结果的动作可能直接退出，页面缺少反馈。
- **采用后的通过标准**　优先覆盖取消订单、退款裁定、下架和撤回。弹窗清楚标明对象和动作。键盘可确认或取消，关闭后焦点返回触发控件。取消时写请求数为 0，确认只触发一次，处理中防止重复触发。

### L1 · 共用组件保留局部旧样式

- **复现与当前表现**　打开订单或报价图片放大弹窗，可见旧米白底和遮罩。作品待审核材料及历史已局部使用 CraftFlow 样式，交易摘要底色等位置仍有差异。
- **采用后的通过标准**　用相同视口和样本，对照现有 CraftFlow 颜色、字体及组件布局。放大图完整可读，弹窗打开、关闭以及焦点恢复正常，审核材料和历史的顺序与内容完整。 [图片弹窗](../../frontend/src/assets/styles/quote.css#L17) · [待审核材料和历史样式](../../frontend/src/assets/styles/craftflow-publication.css#L335)

### L2 · 600px 窄窗下页头遮挡需求报价锚点

- **复现与当前表现**　打开内容较长的创作者需求详情并定位到 `#quotes`。1366、1024 和 760px 下标题可见，600px 下已复现顶部约 17px 被页头遮住。V1.5 的桌面验收从 1366 CSS 像素开始。
- **采用后的通过标准**　若纳入窄窗支持，在 600、760 和 1024px 复查标题及首个操作完整可见。桌面上同时回归需求报价、定标确认、订单授权与订单进度锚点。 [需求报价区偏移](../../frontend/src/assets/styles/craftflow-demand.css#L178) · [V1.5 适配范围](../requirements/requirements.md#L745)

### 交互附项 · 创作者主页补证图片缺少本地文件校验

- **复现与当前表现**　在评价举报补证入口选择超限或类型不合规的文件。选择器的 `accept` 提供类型提示，处理函数检查数量，格式和大小由服务端拒绝。
- **采用后的通过标准**　按现行接口的类型和大小限制验证。不合规文件立即显示对应原因，上传请求数为 0。合法文件可上传，已有附件保留，服务端继续校验。 [补证图片处理](../../frontend/src/views/CreatorPublicView.vue#L115)

### 交互附项 · 地址和品类编辑缺少离页提示

- **复现与当前表现**　打开收货地址编辑或后台品类编辑，修改输入后切换路由或刷新。源码显示未保存内容会随页面状态销毁。
- **采用后的通过标准**　有改动时，取消离开保留草稿，确认离开才丢弃。没有改动可直接离开。地址删除确认、品类弹窗关闭和正常保存后的退出行为继续可用。 [地址编辑](../../frontend/src/views/AddressesView.vue#L39) · [品类管理](../../frontend/src/views/AdminCategoriesView.vue#L31)

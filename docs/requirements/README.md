## 修订方式

1. 明确需要改变的业务行为、原因和影响。
2. 依据明确决定修订当前正文及关联设计、验收项；维持正文状态与确认事实一致。
3. 在当前版本内修订时，将正文同步到当前版本中文副本，验证两份文件逐字节一致。
4. 升级版本时保留上一版本文件及其原有内容，另建新版本中文副本，并将 `requirements.md` 更新为新版本内容；历史文件不随正文覆盖。
5. 按需更新相关索引；纯需求修订不创建开发任务或测试记录，涉及已开始的业务功能时更新其现有任务。

原型、设计或实现与需求冲突时，指出具体冲突并澄清；不要从多个版本各取一部分形成隐含规则。

## 1 引言

### 1.1 编写目的

本文档定义“基于 Spring Boot 技术的手工定制作品分享与交易平台”的功能需求、业务规则、约束条件与交互提示文案，用于统一开发实现与测试验收的口径。文档同时作为毕业设计论文“需求分析”章节的支撑材料，并为后续数据库设计、接口设计与测试用例编写提供依据。

本文档描述的是系统“应当具备什么能力、在什么条件下允许、违反条件时如何反馈”，不涉及具体代码实现、页面视觉稿与部署方案。

### 1.2 项目背景

手工定制类商品的交易与标准化商品存在三点差异：其一，作品展示创作者现在或过去完成的成品，可以仅展示、出售现货或接受同类定制，不是每条作品都有现货；系统按单件现货管理销售，记录其锁定与售出状态；其二，定制需求需要买家描述诉求、创作者给出方案后才能定价；其三，定制交付周期长，制作过程需要被看见，否则买卖双方对进度缺乏共同预期。现货无需再次制作，付款后直接进入待发货。

本系统将作品分享与定制交易合并到同一平台：创作者用作品积累信任，买家从作品产生定制意愿，平台以“需求单—多方报价—订单—进度打卡—评价”的链路承接交易，并在交易完成后把成品重新沉淀为社区作品，形成内容与交易的双向循环。

### 1.3 术语与定义

为避免“作品”“商品”“需求”“订单”等词在不同语境下混用，本文档统一采用表 1-1 的定义。

表 1-1  术语与定义

| 术语 | 定义 |
| --- | --- |
| 作品 | 展示创作者现在或过去完成的手工成品的一条内容记录，不等于可售现货；发布时独立选择是否出售现货、是否接受定制，也可以两个都关闭，仅作展示 |
| 现货 | 创作者手中已经完成、确实可提供且愿意出售的实物；只有开启现货销售并处于可购买状态时才可直购，开启现货销售时按单件管理 |
| 成品直购 | 买家购买作品所对应的那件可售现货，按现货售价下单，支付后直接待发货；不要求重新制作 |
| 同类定制 | 买家以展示作品为参考，请创作者另外制作；须单独创建需求、报价和订单，不购买或占用展示作品的那件现货 |

| 定标 | 买家选择唯一有效报价并同时生成待付款订单的动作；成功后不可更换中标方案，生成订单失败则本次定标不生效 |
| 进度节点 | 仅用于定制订单的固定制作里程碑；现货直购订单不生成进度节点 |
| 认证创作者 | 通过平台资格审核、取得接单与收款权限的账号 |
| 一级品类 | 手工类型的大类，例如皮具、木作、陶艺；创作者认证选择一级主品类 |
| 二级品类 | 某个一级品类下的细分，例如“皮具”下的钱包、卡包；示例不限定后台实际品类 |
| 履约偏差 | 定制节点超出参考计划、定制确认开工超时、订单发货超时等偏离约定节奏的情况；系统展示节点偏差，整单发货超期通知按订单去重，业务资格处置由管理员结合证据决定 |
| 成品公开授权 | 定制订单完成后，由创作者申请、订单买家通过按钮明确同意本次成品展示；授权不包含买家收货资料和聊天记录 |

## 2 项目概述

### 2.1 平台定位与业务模式

平台定位为面向手工定制领域的 C2C 撮合与内容社区，服务对象是具备手工制作能力个人创作者与有个性化定制需求的买家。平台自身不持有商品、不参与生产，主要承担三项职能：为创作者提供作品展示与接单入口，为买家提供需求表达与方案比较工具，为双方提供订单履约与过程可视化的共同依据。

系统支持三种交易形态，三者共用同一套账号、作品与订单体系，但入口与流程长度不同。

成品直购：仅对已上架、开启“出售现货”且现货可购买的作品开放，买家购买创作者手中的那件成品。支付前为待付款，支付成功直接进入待发货；无待开工、制作中或制作进度打卡环节。

定制撮合：买家发布需求单，多位创作者报价，买家对比后定标，流程最长，是本系统的核心形态。

定向定制：买家通过作品或创作者主页发起新需求，定向该名同品类、有接单资格的创作者。一条需求仅有一名受邀者，仅买家及受邀者可见，不进入公开大厅；开放与过期按需求规则判断。展示作品仅作参考，实际另外制作，不占用原现货；报价和定制订单复用统一流程。公开需求允许多名创作者报价和买家对比。

仅展示的作品仍可公开浏览、点赞、收藏和评论，不要求进入交易流程；其是否出售现货、是否接受定制的组合规则见 4.2.1。

### 2.2 用户角色与职责

系统设置三类角色。角色由账号权限位决定，而非账号类型，因此同一账号可以同时具备买家与创作者两种身份，具体规则见 4.1.3。

表 2-1  用户角色与职责

| 角色 | 核心职责 | 典型操作 |
| --- | --- | --- |
| 买家（BU） | 表达需求、比较方案、完成交易与评价 | 浏览作品、收藏、发布需求单、查看报价对比、下单支付、查看进度、评价 |
| 创作者（CR） | 展示手艺、响应需求、按约交付 | 申请认证、发布作品、接需求、提交报价、打卡上传进度、发货、处理售后 |
| 管理员（AD） | 维护平台秩序与内容质量 | 审核认证与作品、处理举报与退款、维护品类、查看数据看板 |

### 2.3 核心业务流程

定制交易按以下流程开展：认证和作品提供创作者发现入口，需求、报价和订单完成撮合，制作进度与发货完成履约，评价沉淀口碑。交易结束后的作品回流由创作者自愿进行，不作为订单完成的前置条件。

第一步，创作者提交入驻申请、3—5 件原创作品及收款资料，管理员一次审核通过后取得创作者权限；平台不宣称完成权威实名认证。

第二步，创作者发布作品，分别选择是否出售现货、是否接受定制，经上架审核后公开展示；两个选项均关闭也可作为作品案例展示。

第三步，买家浏览作品或直接发布定制需求单，需求包含品类、材质、尺寸、预算、需求描述与期望发货时间，支持上传图片。

第四步，同品类认证创作者在公开需求下提交报价，买家比较金额、工期、方案与创作者口碑；定向需求仅由指定创作者报价，买家查看并确认方案。

第五步，买家定标，系统在同一次操作中锁定报价方案、生成唯一待付款订单，并将其余有效报价置为未中标；订单创建失败则整次定标回滚，允许重试。

第六步，买家在订单创建后 24 小时内完成模拟支付；定制订单进入待开工，创作者须在支付后 48 小时内确认开工。

第七步，创作者按五个固定节点打卡上传制作过程，买家实时查看进度与偏差。

第八步，创作者发货，买家确认收货或到期自动确认；买家可评价该订单的商品体验和合作创作者。创作者不评价订单或买家。

第九步，定制订单完成后，创作者点击“申请公开成品案例”，系统通知买家，由买家点击“同意公开”或“不同意”；未回复不能视为同意。同意后创作者手动整理并发布关联作品，继续经过作品审核。已交付给买家的成品案例关闭“出售现货”，可以接受新的同类定制。授权范围、记录与校验见 4.2.6。

## 4 功能需求

本章逐模块定义操作、字段、权限、业务规则与异常反馈，所有功能均须实现，规则条目用于形成校验逻辑与测试用例。

### 4.1 账号与身份

#### 4.1.1 注册、登录与找回密码

- 使用 QQ 邮箱或 163 邮箱接收验证码注册，同时设置密码并填写 2—8 字昵称；注册成功后通过登录入口登录。验证码为 6 位数字，5 分钟有效，注册与密码重置共用邮箱验证码。同邮箱仅最新一次获取的验证码可用，重发后旧码失效，使用成功即作废。
- 同一邮箱只能注册一个账号。邮件须实际发送；发送失败或结果未知时如实提示，不返回发送成功，不创建未完成账号。手机号不参与注册，不发送注册短信。
- 使用邮箱和密码登录，密码采用加盐哈希保存。登录态有效期 7 天，退出即失效，允许多端登录。
- 忘记密码时，向已注册邮箱发送密码重置验证码，校验后设置新密码；验证码按邮箱校验，不区分注册与重置用途；重置成功后该账号所有原登录凭证失效。
- 访问业务页面须先登录；未登录访问时进入登录页，登录成功后返回原目标页面。

#### 4.1.2 个人资料与收货地址

- 支持修改昵称、头像和简介。昵称 2—8 字，头像 jpg/png 且不超过 2MB，简介最多 200 字；不限制昵称按月修改次数。
- 地址最多 10 条，含收件人、手机号、省市区、详细地址；支持增删改和默认地址，不单独填写邮编。首条地址自动设为默认；存在地址时保留唯一默认地址，只能通过设置另一条默认或删除来替换，不能单独取消。删除默认地址后，自动选择剩余地址中创建时间最新的一条，创建时间相同则选择编号最大的一条。
- 下单或定标确认时选择已有地址，没有地址先补充。生成订单即保存地址快照，个人地址后续变化不改写原订单。
- 邮箱和收货信息不公开。订单创作者仅在发货所需范围内查看收货信息；订单地址在建单时固定。未付款发现地址有误时取消后重新下单，定制须重新发布需求并取得报价；已付款发现有误时通过会话与售后处理，不允许直接覆盖地址快照。

#### 4.1.3 双身份与业务资格

- 注册即拥有买家身份，通过认证后增加创作者身份；切换只改变当前会话的默认首页和入口，多端切换互不影响。
- 权限以账号资格、订单关系和状态为准，当前界面身份不能绕过校验；订单、消息和资料不因切换复制或丢失。
- 禁止购买自己的现货、向自己的需求报价。评价只由订单买家发起，创作者不评价买家。
- 创作者可主动暂停接单，暂停后停止新作品发布、新报价及作为创作者的新交易入口；保留以买家身份参与他人交易的权限。恢复接单不能解除后台暂停。
- 后台可以统一暂停账号新业务，包括新作品发布、新需求发布、新报价、定标建单、现货建单和发起新定向需求；暂停持续至管理员人工恢复，暂停及恢复时均记录原因。
- 两类暂停均不阻止登录、已有订单付款、打卡、发货、会话、退款及模拟结算查询；对新业务须同时校验买卖相关方的有效资格及适用的暂停状态，不能通过旧页面绕过暂停。

### 4.2 作品与内容

作品模块用于展示创作者的成品案例，并根据创作者的选择提供现货直购或同类定制入口。作品可以来自现在持有的成品，也可以来自过去已经售出或不打算出售的成品；作品展示、现货销售和接受定制分别判断。

#### 4.2.1 作品发布

仅认证创作者可发布作品。发布页采用“基本信息—工艺参数—交易信息—图文详情”四段式表单，字段定义见表 4-4。草稿可随时保存，提交后进入审核队列。

**作品是一条展示内容，现货是创作者手中已经做好、可以直接出售的实物。** 发布作品不等于出售现货；创作者必须分别选择“是否出售现货”和“是否接受定制”。两个选项互相独立，两个都关闭也可以提交审核，通过后作为作品案例公开展示。

| 出售现货 | 接受定制 | 作品用途 | 买家入口（作品已上架且满足交易条件时） |
| --- | --- | --- | --- |
| 开启 | 开启 | 出售手中这件成品，同时接受另外制作同类作品 | 立即购买、发起同类定制 |
| 开启 | 关闭 | 只出售手中这件成品 | 立即购买 |
| 关闭 | 开启 | 不出售展示的这件成品，但愿意另外制作同类作品 | 发起同类定制 |
| 关闭 | 关闭 | 仅展示过去或现在完成的作品 | 浏览、点赞、收藏、评论，无直购和该作品的定制入口 |

例如，创作者发布一个已经做好的皮包：手里还有且愿意卖，开启“出售现货”；包已经卖了但愿意再做，关闭“出售现货”、开启“接受定制”；只展示过去的作品，两个都关闭。

表 4-4  作品发布字段

| 字段 | 规则 | 必填 |
| --- | --- | --- |
| 作品标题 | 2—30 个字符，不允许纯符号与重复堆词 | 是 |
| 所属品类 | 从平台品类中选最具体的一项：有二级品类时须选二级（如“皮具 → 钱包”），一级下无二级时可直接选一级 | 是 |
| 主图 | 1—9 张，首图作为列表封面，比例建议 1:1 或 4:3 | 是 |

| 尺寸规格 | 按品类填写尺寸或规格描述，无固定尺寸可注明，可附尺寸图 | 是 |

| 成品售价 | 仅开启“出售现货”时填写，0.01—99999 元；仅用于现货直购，不作为同类定制的固定成交价 | 条件必填 |
| 同类定制参考周期 | 开启接受定制时填写 3—180 个自然日，仅用于同类定制参考；现货直购不使用该周期 | 条件必填 |
| 是否接受定制 | 是/否；选“是”表示愿意以该作品为参考另外制作同类作品，与是否出售现货无关 | 是 |
| 作品描述 | 20—2000 字，说明工艺、使用与保养方式 | 是 |
| 制作过程说明 | 0—1000 字，可选，用于展示手工属性 | 否 |

发布行为受以下规则约束，用于控制内容质量与刷屏风险。

同一创作者每日最多首次提交发布 5 件作品，按北京时间自然日统计；保存草稿不计数，同一作品修改重提不作为新作品重复计数。达到上限时禁止新作品提交发布。

标题与描述不得包含联系方式、外链、其他平台店铺名，命中即拦截。

发布页显示简短警告：“请发布本人原创作品，勿重复发布相同内容；违规或重复作品可能被审核驳回或下架。”不自动比对标题、主图或重复铺货，由管理员在审核中判断。

草稿由作者自行保存、修改或删除，不按 30 天自动清理。

交易字段按选项校验：仅展示或仅接受定制时，不要求填写现货售价；只要开启“接受定制”就须填写定制参考周期，实际定制价格和工期以独立报价为准。作品现货价格修改即时生效，已有订单仍按快照结算。

仅开启“出售现货”的作品按一件现货管理，不做批量库存管理；从未开启现货销售的纯展示或仅定制作品不要求有实物库存。单件现货分为可购买 AVAILABLE、已锁定 RESERVED、已售出 SOLD_OUT；创建待付款直购订单时锁定，未付款取消或超时后释放，支付后标记已售出。同一时刻只允许一个未取消且未全额退款的直购订单，不能通过重新切换选项绕过锁定或已售出状态。

现货售出后自动关闭直购入口，保留“已售出”记录；“接受定制”保持原设置，不会随现货售出自动开启或关闭。原订单全额退款且创作者确认成品未发出或已经退回、仍可出售时，才可手动恢复直购，退款不自动恢复销售。

一条作品可以承接多笔同类定制订单，每笔分别创建需求、报价和订单。定制是另外制作，不占用或锁定展示作品的那件现货；现货已售出也不妨碍继续接受定制。

关闭现货销售或接受定制，只停止对应的新交易入口，不取消已有订单。已上架作品关闭这两个选项后仍可继续展示，无需因此下架。

#### 4.2.2 上架审核

认证与作品审核独立进行，所有作品（包括纯展示作品）提交后由一名管理员检查图片、描述、品类、原创性和违规内容。

表 4-5 作品审核状态

| 状态 | 标识 | 说明 |
| --- | --- | --- |
| 草稿 | DRAFT | 保存未提交，仅本人可见 |
| 待审核 | PENDING | 已提交，等待审核；可撤回后修改 |
| 已上架 | ONLINE | 公开展示，可搜索；交易入口还须满足对应开关和资格 |
| 已驳回 | REJECTED | 附原因，可修改重提 |
| 已下架 | OFFLINE | 作者或管理员下架，可修改重提 |

驳回必须说明原因。纯展示或仅接受定制的作品不因没有现货价格而驳回；重复内容由管理员人工判断。

已上架作品修改图片、标题、品类、正文等内容时转待审核，通过后重新公开；只调整交易开关（开启或关闭现货销售、接受定制）、现货价格或定制参考周期即时生效，保持已上架状态，已有订单不受影响。重新开启直购仍须符合原现货未锁定、未售出等条件；关联已交付定制成品的案例不得开启直购。

下架停止新浏览交易入口，不取消已有订单。所有上下架、审核和修改均留痕，交易仍按订单快照履约。

#### 4.2.3 浏览、检索与筛选

- 首页默认最新发布，分类采用两级品类（如一级“皮具”下可细分二级“钱包、卡包”；木作、陶艺、编织、饰品等也属于一级大类示例）。
- 关键词匹配标题和描述；支持品类、现货价格区间、是否可直购、是否接受定制筛选，可组合使用。
- 排序支持最新、现货价格升序及降序。价格条件只匹配当前可购买现货；未设置价格的纯展示作品不能当成 0 元商品，价格排序时放在有可购价格的作品之后。
- 列表每页 20 条；无结果时提示调整条件。未限制交易方式时包含已上架纯展示作品，待审核和下架作品不进入公开检索。
- 详情展示图片、材质、规格、工艺介绍、作者信息及适用的售价或定制参考工期；依照交易开关和当前资格显示直购、定制按钮。
- 创作者主页展示简介、主品类、地区、已上架作品、平均评分、评价数量及完成订单数；关注入口在主页和作品作者信息处提供。暂停新业务时展示暂停提示并关闭相应交易入口，已有上架作品仍可按原可见性展示。

#### 4.2.4 互动功能

系统提供点赞、收藏、作品公开评论和关注功能。

- 点赞与收藏：同一用户对同一作品各保留一次有效记录，可取消；展示总数。个人中心可查看自己的收藏作品，失效内容提示已下架。
- 作品评论：登录后发表 10—500 字文字，可附最多 3 张图片；列表显示作者、时间、文字及图片，支持分页查看。用户只能删除自己的评论，创作者不能删除他人评论。
- 关注：可关注或取消关注创作者，在个人中心查看关注列表；关注关系不自动获得陌生人私聊权限。
- 评论经文本过滤后提交，违规时保留输入并提示修改。作者及买家都可举报违规评论，管理员核实后处理。
- 作品发布按 4.2.1 限流，会话消息按 4.8.4 限流。

作品评论用于公开讨论；订单评价用于已完成交易反馈；需求及订单沟通统一使用会话，不额外建立节点评论体系。

评论文字为必填，图片可不附；仅图片而无文字的评论不能提交。

#### 4.2.5 内容治理与举报

举报入口覆盖作品、评论、评价和创作者主页。选择盗图、虚假宣传、站外引流、辱骂等理由并填写说明或证据。同一用户对同一对象有处理中举报时合并补充，避免重复任务。

举报提交后进入待处理，管理员查看内容和证据，决定不成立或采取下架、隐藏违规内容、统一暂停新业务等措施，说明原因后标记已处理并通知举报人与被处理人。可依据补充证据更正结果、恢复内容或恢复新业务，保留提交时间、处理时间及历次处置记录。用户删除自己的评论与管理员隐藏内容分别记录，不能删除原交易、资金或履约证据。

对处置有异议时可补充证据，由管理员核查、更正并留痕，提交异议本身不暂停已生效处置。正常差评不因评分低而删除，作者不能自行抹去不利评价。

#### 4.2.6 定制成品公开授权与案例发布

1. 仅已完成定制订单的创作者可在授权未申请时，于订单详情点击“申请公开成品案例”。系统将该订单的授权状态改为待回复，记录申请时间，并通知订单买家。
2. 仅该订单买家可在授权待回复时，于订单详情点击“同意公开”或“不同意”。系统记录授权状态和回复时间，并通知创作者；未回复始终保持待回复，不因等待时长、已读或聊天内容自动视为同意。
3. 授权仅覆盖本次定制成品的展示，不包含买家的收货资料和聊天记录。服务端依据订单上的明确授权状态校验，聊天消息不能作为公开授权依据。
4. 买家同意后，创作者手动整理图片、描述并发布关联作品，作品保存来源订单编号，仍遵守作品发布资格、内容规则及上架审核。系统不自动复制图片或自动发布；无授权或关联他人订单时不得提交案例审核，也不得通过修改作品关联绕过校验。
5. 已交付买家的成品案例必须关闭“出售现货”，发布及后续修改时均校验；创作者可以选择接受新的同类定制，也可以仅作展示。
6. 订单保存授权状态、申请时间和回复时间；作品保存来源订单编号。申请、回复及通知须保持一致，重复申请或重复回复不重复生成记录和通知，也不能覆盖已经作出的回复。授权不改变订单、退款、评价或结算状态及期限。

- 只有公开需求进入大厅。定向从作品或主页发起时带入该作者，一条需求只允许一名受邀者；发布后不能追加或更换，不能同时改成公开需求。修改范围或受邀者须关闭原需求并复制新建。
- 定向关系确定需求的可见性和报价资格，开放与过期依据需求状态判断。聊天或查看不会改变需求的报价状态和期限。
- 定向需求统一按 4.3.4 判断开放与过期：发布满 7 天且无有效报价才过期，有效报价尚存时仍可定标。指定创作者可在需求开放时撤回重报，不能向其他创作者披露需求和会话。
- 需求关闭或过期后不能新报价；未形成订单的会话归档只读。已经形成订单的双方继续通过关联会话沟通，即使订单已完成、已取消或已退款，定制需求因取消或退款关闭也不改变该权限。其他创作者始终无权查看该定向需求。
- 需求只展示买家昵称，不收集收货地区，不推断姓氏、性别，不公开完整地址或联系方式；完整收货地址在定标建单时选择并保存快照。
- 草稿可编辑；发布后正文及范围立即锁定。需要修改时在定标前关闭原需求并复制新建，旧报价、会话和定向关系不继承。

#### 4.3.2 需求大厅与创作者响应

公开需求大厅仅认证创作者可浏览；普通买家查看自己的需求。认证创作者默认按本人认证主品类查看公开需求，也可查看其他品类，并按预算及发布时间筛选。详情包含材料、规格、预算、期望发货日和参考图，不展示买家私密交易信息。创作者同时具备买家资格，可发布自己的需求，权限不由当前界面身份决定。

- 报价：已认证、主品类匹配且有接单资格才可提交；定向还须是该需求唯一指定创作者，且需求处于开放状态。
- 咨询：围绕可访问需求发起买卖双方一对一站内会话，不设公开需求留言区。
- 每名创作者每自然日最多提交 20 次报价，撤回后重报同样计入当天次数；咨询消息按会话限流，不与报价混合计数。

#### 4.3.3 需求沟通

定标后中标创作者的原需求会话关联订单并继续使用，未中标者的会话归档只读；需求关闭或过期且未形成订单时会话也归档。已经形成订单的双方在订单已完成、已取消或已退款后仍可沟通和补充证据，不能因此重新开放付款、制作节点或退款申请窗口。内容治理与频次限制统一按 4.8 执行，不单独建立需求评论或节点评论。

### 4.5 订单与交易

订单按现货 STOCK 和定制 CUSTOM 两种履约类型分流。所有资金动作均模拟，仍记录支付、退款及结算数据，不建立用户余额钱包。

#### 4.5.1 下单与支付

- 现货从作品详情下单，须已上架、开启现货销售且可购买；选择地址后锁定这件成品，商品金额取现货售价。
- 定制从定标生成订单，商品金额、工期、材料、方案及效果图取中标报价快照；同类定制不占用展示作品现货。
- 金额统一为：买家实付金额 = 商品成交金额；创作者应结算金额 = 买家实付金额；全额退款金额 = 买家实付金额。商品成交金额在建单时保存快照，由服务端确定。
- 仅保留一个模拟支付入口，记录金额、时间、流水号和结果，不建设余额、充值、钱包、提现。收款账户真实保存，但不接入真实扣款或转账。
- 待付款可取消；创建满 24 小时未付款自动取消，现货释放锁定，定制关闭需求。支付与超时取消只能一个生效，重复支付不重复记账。
- 订单展示类型、编号、双方、标题、商品成交金额、买家实付金额、地址、约定发货时间、售后条款及操作历史；创作者和管理员可查看应结算金额及结算状态。
- 定制支付前确认开工后不支持单方无理由退款；现货按现货条款处理，不套用定制限制。

#### 4.5.3 履约、发货与收货

- 现货支付后 48 小时内发货；定制工期从支付次日零时起算，包含开工等待，不含物流。最终发货截止时间及节点计划在支付成功时计算。
- 发货仅填写 8—30 位字母数字运单号，系统记录发货时间；确认收货前可更正单号，保留原单号、新单号、更正人和时间并通知买家，更正不重置原发货时间及自动确认倒计时。不接物流轨迹，不另由卖方手动更新揽收、运输和签收。
- 买家确认收货后完成；发货满 7 天且没有处理中售后自动确认，开放评价。正常售后申请仅在已付款履约中或原完成时间后 7 天内发起。
- 超过约定发货截止且仍未发货时展示超期，向双方发送一次性通知，具体去重与售后期间的处理见 4.6.4。超期不自动取消、退款或暂停账号，未进入售后或终态时仍可继续履约。
- 订单地址、约定发货日及初始节点计划在各自确定后保持固定。聊天可以说明延误及补充证据，但不改变系统约定；初始计划与实际提交时间分别保留。

#### 4.5.4 售后与退款

系统提供全额退款。普通退款由一名管理员审核；定制支付满 48 小时且仍未开工的无责退款由系统校验后直接执行。

1. 买家选择退款原因，填写 20—500 字说明和最多 3 张凭证图；同一订单同时仅一条处理中申请，进入售后中并保存原状态。
2. 普通申请直接进入管理员待处理队列并通知双方。买卖双方可多次追加说明和证据，每次文字最多 500 字、图片最多 3 张，允许纯文字、纯图片或图文，至少一项非空，原申请及历次补证不可覆盖。退款由管理员依据证据裁定。定制支付满 48 小时且仍未开工的无责退款，系统在事务中重检后直接执行，同时保留退款申请、依据和流水。
3. 已发货或已收货的申请由管理员核实是否退货、退回单号或凭证；退货通过原订单会话沟通和追加证据，不另设退货子状态。需退货时核实原成品已退回后才能批准退款，无需退货时必须记录依据；核验与最终裁定一同保存。由一名管理员作出结论。
4. 管理员查阅订单快照、制作进度、会话和凭证，支持退款或驳回并填写原因，保存处理时间并通知双方。
5. 支持退款时返还全部买家实付金额，记录退款流水，并在同次操作中取消待结算；保留原支付金额和记录，不能重复退款或继续结算。
6. 成功后订单已退款、定制需求关闭；现货不自动重售，须原成品仍可售后手动恢复。驳回或买家撤回恢复原履约状态，不重开原需求和竞价。
7. 退款幂等，不能重复退还。履约及会话记录保留，退款对结算的处理见 4.5.5。

退款申请状态为待管理员处理 WAIT_ADMIN、已退款 REFUNDED、已驳回 REJECTED、已撤回 WITHDRAWN。待处理时允许双方追加证据、买家撤回或管理员裁定；管理员批准与退款执行在同次操作中成功或失败。系统无责退款直接形成已退款记录。终结后的原申请及证据不得覆盖；在原申请窗口内再次申请须生成新记录，不重开原订单的完成时间或售后窗口。

#### 4.5.5 模拟结算

- 两类订单的创作者应结算金额均等于买家实付金额。例如商品成交金额 100 元，买家实付 100 元，创作者应结算 100 元；若结算前全额退款，则退还买家 100 元并取消待结算。
- 支付成功记录待结算金额；未付款或未付款取消的订单不产生待结算。订单原完成时间起满 7 天、未全额退款且无处理中售后，才按已审核收款账户生成模拟结算流水并保存账户快照，结算状态改为已结算。此操作不实际转账，不产生可消费余额或提现入口。
- 结算前全额退款时，待结算记录改为已取消，保留原实付和应结算金额用于追溯，该记录不再产生结算流水，也不计入待结算或已结算金额。
- 退款受理、退款执行和结算须互斥校验，存在处理中退款不能结算；同一订单仅可成功结算一次，重复请求和重复扫描不多生成流水。
- 退款申请窗口以订单原完成时间起 7 天为界，售后驳回或撤回不重开窗口。窗口内已提出的申请必须等结论再判断结算；恢复已完成且已满 7 天、无其他处理中售后时可结算。结算完成后资金流水只读，退款接口仅受理规定窗口内的申请。
- 创作者在订单和收入记录查看实付金额、应结算金额、待结算/已结算/已取消及脱敏收款账户；管理员查看资金和账户快照。保留真实收款资料的录入审核，不接入真实结算系统。

| 4 | 质检 | QC | 规格、外观、工艺检查 | 10% |
| 5 | 包装发货 | SHIPPING | 包装、保护及运单号提交 | 10% |

支付后从支付次日零时计算累计 15%、35%、80%、90%、100% 的参考完成日，按总工期向上取整到自然日。节点参考计划计算后固定，用于展示实际偏差，不因固定占比直接判定违约；最终约定发货日是双方履约依据。整单发货超期通知见 4.6.4。

节点状态：未开始 NOT_STARTED、已解锁 UNLOCKED、已打卡 CHECKED、已跳过 SKIPPED。确认开工解锁首节点；前节点打卡或跳过才解锁下一节点。

#### 4.6.2 创作者打卡

- 每节点 1—6 张当前阶段实拍图、5—500 字说明，记录完成内容和待沟通问题；使用服务器提交时间。
- 原记录不能删除或覆盖，履约期间可对已处理节点追加补充，保存每次提交时间。补充允许纯文字、纯图片或图文，至少一项非空；文字最多 500 字，图片最多 6 张。订单进入售后中或终态时不得追加。
- 只有打样打版可填写原因和 10—500 字说明跳过，保留跳过时间；其他节点必须处理。
- 前四节点处理完进入待发货；第五节点图文、运单号和系统记录的发货时间在确认发货时同时生效，不能先完成发货节点再等待发货。
- 图片真实性通过人工审核及争议证据判断。打卡成功通知买家。

#### 4.6.3 买家视图与沟通

- 展示已完成数量/5、阶段计划时间、实际时间、偏差及图集；跳过计入完成，展示原因与跳过时间，不伪造打卡时间。
- 4/5 表示制作完成待发货，5/5 表示已经发货，不等于买家已收货。
- 买家只读，不修改节点；“讨论此进度”跳转订单会话，可在消息中引用节点。
- 订单已完成、已取消或已退款后，制作节点与初始计划仅供查阅，不得继续打卡或追加节点补充；必要补充证据通过订单会话提交，原记录保留作为评价与售后依据。

#### 4.6.4 超期展示与整单提醒

节点展示初始参考完成日、实际完成或跳过时间和偏差；尚未处理且已过计划时显示超期。已处理节点按其实际时间展示历史偏差，不能随查询时间继续增加。

现货和定制订单均在已付款、尚未发货、未终止且超过约定发货截止时，向双方发送一次整单发货超期通知；按订单和异常类型去重，重复扫描、重启或售后恢复不重复发送。售后处理中暂停发送，驳回或撤回恢复履约后重新判断；尚未发送过且仍符合条件时补发一次。

售后暂停不改写节点计划或约定发货日，售后占用时长仅用于顺延已发货订单的自动确认收货时间。超期不触发自动处罚，由管理员结合真实履约与沟通证据决定是否统一暂停新业务。

### 4.7 评价与口碑

本模块提供买家单向评价和基础口碑展示，依据有效评价和完成订单计算公开统计。

#### 4.7.1 评价规则

表 4-13 买家评价字段

| 字段 | 要求 |
| --- | --- |
| 总体评分 | 1—5 星，评价现货展示或定制约定的符合程度及合作体验 |
| 文字 | 10—500 字 |
| 图片 | 0—3 张 |

仅订单买家可在订单原完成时间后 7 天内评价，每单一条，同时关联订单和合作创作者；创作者不能评价买家，陌生用户不能直接评价创作者。售后处理中、已取消和已退款订单不能新建评价。

评价提交后不可自行修改，每笔符合条件的订单均可评价。评价图片可不附，最多附 3 张，图片不能替代必填文字。合法差评照常展示；未评价不自动生成默认好评。

#### 4.7.2 基础口碑展示

- 展示有效评价平均星级、评价数、好评率及完成订单数，平均星级保留一位小数。
- 4—5 星为好评，好评率为好评数/有效评价数；无评价显示暂无评价，不除零、不默认低信用。
- 完成订单数按当前未退款的已收货完成订单统计；进入售后但尚未退款仍有完成事实，全额退款后排除该订单。
- 不以评分自动降权、限制报价或冻结资格；创作者和报价对比页使用同一统计口径。

#### 4.7.3 评价治理

文本违法违规在提交时提示修改并保留输入。已发布评价可举报，管理员结合交易和会话核实后隐藏或删除违规内容，记录原因。

被隐藏、删除或对应订单发生全额退款的评价不计入公开评分和好评率；退款评价保留在订单记录，不再作为公开交易口碑。正常差评不因卖方不满意而删除。

### 4.8 站内实时消息

消息分系统通知与一对一会话。需求沟通和订单履约使用同一会话体系，节点讨论通过订单会话进行。

#### 4.8.1 事件与通知

表 4-14 主要消息事件

| 事件 | 时机 | 接收方 |
| --- | --- | --- |
| 认证、作品审核 | 通过或驳回 | 申请人/作者 |
| 定向需求 | 发布给唯一指定创作者、需求关闭或过期 | 指定创作者；关闭或过期结果同时告知买家 |
| 报价变化 | 新报价、撤回、失效 | 买家及对应创作者 |
| 定标结果 | 唯一订单创建成功 | 中标与落选创作者 |
| 订单状态 | 支付、开工、取消、发货、收货 | 买卖双方 |
| 运单号更正 | 发货后更正运单号 | 买家 |
| 制作进度、发货超期 | 打卡成功、整单发货超期的一次性提醒 | 打卡通知买家；发货超期通知双方 |
| 售后、模拟结算 | 申请、撤回、裁定、退款、结算或取消待结算 | 对应业务双方；结算金额只给创作者 |
| 成品公开授权 | 创作者申请、买家同意公开或不同意 | 申请通知买家，回复结果通知创作者 |
| 举报与账号处置 | 举报结果、暂停新业务及人工恢复 | 相关用户 |

通知可查看、标已读及跳转业务，不能直接回复。通知记录不因实时推送失败丢失。

#### 4.8.2 会话与通知列表

- 消息中心分通知和会话，按最新时间排序，分别统计未读，汇总超过 99 显示 99+；进入会话标已读。
- 只围绕有权限的需求或订单发起会话，关注和历史交易本身不开放无关联私聊。
- 公开需求由买家和符合条件创作者沟通，定向由有效受邀者沟通；未形成订单且需求已关闭或过期时，会话归档只读。定标后，未中标创作者的会话归档只读，中标创作者的原需求会话保留历史并关联订单，继续使用。
- 只要双方已形成订单，订单已完成、已取消或已退款后仍可在该订单会话沟通、补充证据；关联需求因订单取消或退款而关闭，不触发订单双方会话归档。即使创作者暂停新接单也保留入口，不提供会切断必要沟通的拉黑功能。
- 继续聊天仅补充沟通和证据，不重新开放已经结束的付款、制作节点、评价或退款申请窗口，不恢复已关闭需求的报价与定标。
- 会话显示关联需求/订单与状态，可跳转；历史分页查询，消息记录持续保留，归档仅改变发送权限。

#### 4.8.3 实时推送与离线补偿

- 使用 WebSocket，凭登录凭证由服务端确定身份，不相信客户端任意上报的用户编号。
- 消息先保存再推送，同一用户多端可接收；消息唯一编号用于展示去重，已读状态以服务端为准并同步刷新。
- 在线消息端到端目标不超过 3 秒；离线登录后查询未读，历史每次最多 50 条分页补拉。
- 断线有限重试，失败提示刷新或重新连接，仍可读取已经保存的消息。

#### 4.8.4 消息限制

单条支持 1—500 字文字或最多 3 张图片，允许纯图片，文字和图片不能同时为空。同一发送人在同一会话 60 秒最多 20 条，超限暂停 60 秒；10 秒内重复发同一文本予以拦截，之后正常相同回复不永久禁止。

文字过滤脚本、明显辱骂和站外引流；图片采用举报人工核实，不承诺 OCR、二维码自动识别。合法收货、物流与收款结构化字段按各自权限处理，不因联系方式规则误拦。系统通知不占普通聊天额度。

### 4.9 后台管理

#### 4.9.1 审核中心

集中展示创作者申请和作品审核队列，按提交时间排序。详情含材料、历史结论及本次变化，一名管理员通过或驳回，驳回说明理由，通知申请人。收款资料随创作者申请一次审核，认证通过后只读；处置更正说明依据并保留原结论。

#### 4.9.2 用户、内容及品类管理

- 按邮箱、昵称、认证状态查询用户，查看与处置相关的作品、需求和订单。
- 统一暂停账号的新业务或人工恢复，说明原因和恢复条件并留痕，范围见 4.1.3。暂停持续至人工恢复，不改变认证结论；管理员恢复不能覆盖创作者本人的暂停接单选择。
- 受限账号不能开展新业务，但保留现有订单履约、会话和售后；不能用完全禁止登录与必须履约相互矛盾的设置。
- 举报队列显示对象、说明和证据，可判定不成立或执行下架、隐藏及暂停新业务，通知结果；可记录依据后恢复内容或新业务，保存提交时间和处理时间，不能改写原订单、进度和资金流水。
- 维护两级品类，可新增、编辑、停用；停用项新建不可选，历史保留原值。

#### 4.9.3 订单、退款与结算记录

按编号、状态、类型、时间和金额查询订单，异常和售后优先展示；详情含约定快照、付款、发货、会话和制作记录。

一名管理员处理退款和纠纷，检查必要退货凭证并说明结论。查询实付金额、全额退款金额、应结算金额、已审核收款账户及待结算、已结算、已取消记录，不能重复退款或结算。

审核、上下架、内容隐藏与恢复、暂停新业务与恢复、退款、结算及现货恢复销售记录操作人、时间、对象、原因和结果；前台用户不能修改日志。

| --- | --- |

## 5 非功能需求

### 5.1 性能与可用性

测试参考单机 50 并发、作品 500 件、需求 200 条、订单 300 笔、消息 20000 条。普通列表目标 1.5 秒内，对比页 2 秒内，在线消息 3 秒内；列表统一分页。性能按测试环境记录，不承诺所有公网网络上传同样耗时。

### 5.2 安全与隐私

- 服务端验证登录、权限、资源归属及业务状态；订单、报价、会话不能越权访问。
- 密码加盐哈希；真实收款账户和姓名限本人及必要管理员访问，其他地方脱敏；不强制收集身份证资料。
- 图片检查实际类型和大小，数据库使用参数化访问，文本输出转义，避免脚本注入。
- 报价、发消息按各自规则限流；支付、退款、定标、结算保证重复请求不多执行。
- 保存交易约定、资金流水及重要操作日志，不因普通删除草稿或用户改资料改写历史。

### 5.3 使用范围

支持主流 Chrome、Edge 的电脑 Web 端，最小适配宽度 1366 像素；不做移动端、小程序验收。保留 7 天登录有效期与退出失效，不设置 30 分钟无操作强制锁定。

表单错误定位字段并保留内容，上传和长操作显示状态；支付等超时时先查业务结果，不把网络异常等同于交易失败。

### 5.4 数据保留与历史一致性

- 交易约定、支付与退款流水、模拟结算记录、制作进度、会话消息及重要操作日志持续保留，保留其关联的必要图片和证据。
- 删除草稿、修改个人资料、下架作品、关闭需求或归档会话，不得删除已有交易证据或破坏历史引用。
- 订单金额、方案、地址和收款账户等快照按业务发生时保存；成品公开授权状态及申请、回复时间保存在订单，关联作品保留来源订单编号。业务状态变化通过状态记录、补充证据和操作日志反映，原始资金流水及履约证据不可覆盖。

| UC-39 | 授权案例发布与审核 | 未获同意或关联他人订单时不能提交案例审核；同意后由创作者手动发布并保存来源订单编号，正常审核后才公开；不公开买家收货资料或聊天，案例发布及修改均不能开启现货销售，可以接受新的同类定制 |
| UC-40 | 订单结束后的会话 | 已形成待付款订单后取消、完成订单或全额退款后，双方仍能在同一订单会话发送文字、图片及补证；定制需求随取消/退款关闭不影响中标会话，未中标会话仍只读；继续聊天不能恢复已结束付款、节点、评价或退款申请窗口 |

## 附录 A 状态流转说明

### A.1 创作者认证

未申请→待审核→已认证或已驳回；待审核撤回→未申请；已驳回修改重提→待审核。认证结论与新业务暂停分开，不通过暂停将已认证改成未认证。

后台新业务正常→人工暂停→人工恢复；创作者接单开启→本人暂停→本人恢复。两类控制独立校验、互不覆盖，均不关闭旧订单履约权限。认证由一名管理员审核，收款资料随同审核，通过后只读。

### A.2 定制需求与定向关系

草稿→待响应→报价中；全部报价消失，发布未满 7 天→待响应，满 7 天→已过期；待响应/报价中主动关闭→已关闭；报价中定标同步建单→已定标；已定标支付→交易进行中，未付款取消→已关闭；交易进行中全额退款→已关闭；订单完成且 7 天售后窗口结束、无处理中售后→已完成。

定向关系在发布时固定唯一指定创作者。需求开放时允许指定创作者报价和撤回重报；未形成订单且需求关闭或过期时，会话归档只读。中标原会话关联订单，订单已完成、已取消或已退款后继续沟通；未中标会话归档只读。公开与定向使用相同的需求过期规则，不把已定标需求按无有效报价过期。

### A.3 报价

提交→有效报价 ACTIVE；有效且未到期时可选中→已中标 AWARDED，其他有效报价→未中标 LOST；撤回、到期或需求关闭→已失效 EXPIRED。只有有效报价约束同需求同创作者唯一，保留多次重报历史，不对所有历史设不可重复组合约束。

中标与落选保持历史，不因订单取消恢复。公开报价校验同品类资格，定向报价还须是唯一指定创作者；所有提交与重报均校验需求开放、有效报价数量及当日报价额度。

### A.4 订单与结算

现货：待付款→支付后待发货→已发货→已完成。定制：待付款→待开工→制作中→前四节点处理完待发货→第五节点图文、运单号及发货时间同时生效后已发货→已完成。

未付款主动取消或超时→已取消。已付款且符合申请条件的订单→售后中；退款成功→已退款；驳回或撤回→进入售后前的状态。售后处理中不同时开工、推进节点、发货或收货；恢复已完成不重设最初完成时间，恢复已发货只顺延实际售后占用时长。订单地址与约定发货日保持固定，已完成、已取消或已退款后节点只读。

普通退款申请→待管理员处理 WAIT_ADMIN→已退款 REFUNDED、已驳回 REJECTED 或已撤回 WITHDRAWN。系统无责退款经重检后直接形成已退款记录。退款批准、订单终止、定制需求关闭、取消待结算和退款流水须同时生效，失败不能部分提交。

资金：支付成功→待结算 PENDING；订单原完成时间起满 7 天、未全额退款且无处理中售后→已结算 SETTLED；结算前全额退款→已取消 CANCELLED。创作者应结算金额等于买家实付金额，已取消记录保留原金额，但不计入待结算或已结算金额。交易状态和模拟结算状态分开，未付款不产生待结算；结算和退款互斥且幂等。

已完成、已取消或已退款不关闭订单双方会话；继续聊天不恢复已结束的付款、节点、评价或退款申请窗口。

### A.5 制作节点

未开始→确认开工或前节点处理后已解锁→提交图文后已打卡；仅打样可从已解锁→已跳过。第五节点从已解锁→图文、运单号及发货时间同时生效后已打卡。跳过计完成度但不伪造打卡时间，追加不覆盖原记录，节点沟通进入订单会话。

### A.6 作品审核与现货

草稿→待审核→已上架或已驳回；待审核撤回→草稿；已驳回修改→待审核；已上架→主动/后台下架后已下架；已下架修改→待审核。展示内容改动重审；交易开关、现货价格和定制参考周期即时更新，保持已上架，按 4.2.2 校验。

审核、是否出售现货、是否接受定制分别保存。两个开关全关仍可展示。开启现货时可购买→创建待付单后已锁定→支付后已售出；未付取消可回可购买；全额退款且创作者确认成品未发出或已退回可售后手动恢复。定制另行制作，不占现货；原现货售出不改变定制开关。

### A.7 定制成品公开授权

未申请 NONE→已完成定制订单的创作者申请后待回复 PENDING→订单买家通过按钮选择同意公开 APPROVED 或不同意 REJECTED。申请时记录申请时间，回复时记录回复时间；未回复保持待回复，不自动转为同意，重复操作不覆盖已作出的回复。

只有同意公开后才允许创作者手动提交关联案例，作品保存来源订单编号并经过正常审核；公开范围仅为该次定制成品，不能包含买家收货资料和聊天记录。已交付案例关闭现货销售，可以接受新的同类定制。授权状态不替代作品审核或改变订单状态。
